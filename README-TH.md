# Smart POS — ROUND 7

## ติดตั้ง
1. ใช้กับ Supabase โปรเจกต์ใหม่/ฐานข้อมูลว่างเท่านั้น เพราะ CREATE TABLE IF NOT EXISTS ไม่ได้แปลงฐานข้อมูลเก่าให้ตรงสคีมาโดยอัตโนมัติ
2. เปิด SQL Editor แล้วรัน `SMART-POS-SETUP.sql`
3. ตั้งค่า Supabase URL และ anon/publishable key ในหน้าโปรแกรม ห้ามใส่ service_role key ใน HTML
4. อัปโหลด `index.html` ไปยัง GitHub Pages
5. ทดสอบตาม `TEST-PLAN-TH.md` ก่อนใช้กับยอดเงินจริง

## รอบ 7
เปิดกะและรายการเงินเข้า/ออกมือซิงค์ผ่าน RPC; เจ้าหนี้ถูกสร้างโดย `receive_goods`; ถอนสิทธิ์เขียนตรงตาราง shifts, cash_ledger และ accounts_payable

## ข้อจำกัด
ยังต้องทดสอบ SQL กับ Supabase จริงและทดสอบธุรกรรมหลายอุปกรณ์ก่อนใช้งานจริง PIN ฝั่งหน้าเว็บไม่ใช่ตัวตนที่เซิร์ฟเวอร์ยืนยันได้ด้วยตัวเอง


## หมายเหตุ Round 8
ใช้ SQL ชุดนี้กับ Supabase ใหม่/ฐานข้อมูลที่มี schema ตรงตามไฟล์เท่านั้น การเพิ่ม `return_items.product_id` ใช้ `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` เพื่อรองรับฐานเดิม แต่ไม่ได้แปลงโครงสร้างเก่าที่แตกต่างจากไฟล์นี้ทั้งหมด หลังติดตั้งให้ทดสอบคืนสินค้าบางส่วน/คืนครบ/คืนซ้ำ/คืนเกินจำนวนก่อนใช้กับยอดขายจริง


### หมายเหตุเรื่องประวัติผู้ทำรายการ (Round 9)
ระบบแยก `actor_user_id` ซึ่งยืนยันจาก Supabase Auth ออกจาก `cashier_user_id` ที่เลือกในหน้า POS เพื่อไม่ให้การเลือกชื่อพนักงานในเบราว์เซอร์ถูกตีความว่าเป็นตัวตนที่เซิร์ฟเวอร์ตรวจสอบแล้ว ทั้งนี้ PIN-only ยังต้องมีการตรวจสอบฝั่งเซิร์ฟเวอร์เพิ่มเติมหากต้องการ audit ที่เชื่อถือได้ระดับความปลอดภัย


### Round 10: รายงานกำไรขั้นต้น
หลังติดตั้ง SQL ให้เรียก RPC `get_profit_report` โดยส่ง `p_from` และ `p_to` เป็น ISO timestamp หรือ `null` เพื่อดึงรายงานรายบิล ผู้ใช้ต้องผ่าน Supabase Auth ที่ผูกกับบัญชีร้านก่อน ค่า `cost_missing=true` หมายถึงข้อมูลต้นทุนของบิลเก่าหรือรายการที่ยังไม่มี snapshot ต้องตรวจสอบก่อนใช้สรุปกำไร


## Round 11: ตรวจยอดปิดกะ
หน้าเว็บรุ่นนี้เรียก `get_shift_reconciliation` จาก Supabase ก่อนปิดกะ ต้องติดตั้ง `SMART-POS-SETUP.sql` รุ่นเดียวกันก่อนใช้งาน หาก RPC ยังไม่มี หน้าเว็บจะรายงานข้อผิดพลาดและไม่ปิดกะ


## ข้อกำหนดเพิ่มเติมใน Round 12
ทุกการขาย การคืนสินค้า และการรับชำระหนี้ต้องผูกกับกะที่เปิดอยู่ และรายการคืน/รับชำระต้องมีรหัสอ้างอิงที่ไม่ซ้ำ หากมีคิวเก่าที่ไม่มีข้อมูลเหล่านี้ อย่าลบคิวหรือเปลี่ยนรหัสโดยไม่ตรวจสอบผลใน Supabase ก่อน


### Round 13 — รายงานกำไรขั้นต้นในหน้าโปรแกรม
หน้า “ขาย, ลูกหนี้ & คืนสินค้า” มีส่วนรายงานกำไรขั้นต้น เรียก RPC `get_profit_report` จาก Supabase พร้อมตัวกรองวันที่ การเปิดรายงานต้องมี SQL รุ่นเดียวกันกับไฟล์นี้และมี Supabase Auth session


## ตรวจสอบ schema หลังติดตั้ง (Round 14)
หลังรัน `SMART-POS-SETUP.sql` แล้ว ให้รันไฟล์ `VERIFY-SCHEMA.sql` ใน Supabase SQL Editor เพื่อตรวจ RPC, คอลัมน์, RLS และ idempotency key โดย query นี้อ่านข้อมูลโครงสร้างเท่านั้น ไม่แก้ข้อมูลร้าน
